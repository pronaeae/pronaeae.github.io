운영체제에서 인터럽트가 왜 필요한지, 어떤 종류가 있는지, 입출력 과정에서 어떻게 사용되는지 정리한다.

## 인터럽트의 사전적 의미

끼어들다, 중단시키다 정도의 의미를 가지고 있다.
프로그램을 실행하는 도중 예기치 않은 상황이 발생하면 실행 중인 작업을 중단하고 발생한 상황을 처리한 후 다시 실행 중인 작업으로 복귀한다.

## 인터럽트의 종류

외부 인터럽트, 내부 인터럽트, 소프트웨어 인터럽트로 나뉠 수 있다.

## 외부 인터럽트

### 전원 이상 인터럽트

- 정전, 파워 이상 등

### 기계 착오 인터럽트

- CPU의 기능적인 오류

### 외부 신호 인터럽트

- 키보드로 인터럽트 키를 누른 경우
- 외부장치로부터 인터럽트 요청이 있는 경우

### 입출력 인터럽트

- 입출력장치가 데이터 전송을 요구하거나 전송이 끝나 다음 동작이 수행되어야 할 경우
- 입출력 데이터에 이상이 있는 경우
- CPU가 장치 상태를 계속 확인하지 않아도 되도록 장치가 CPU에게 알림을 보내는 경우
- DMA처럼 장치가 메모리에 직접 접근해 작업을 끝낸 뒤 CPU에게 완료를 알리는 경우

## 내부 인터럽트

### Trap

- 잘못된 명령이나 데이터를 사용할 때 발생한다.

### 프로그램 검사 인터럽트

- Division by zero
  - 0으로 나누는 연산은 정의할 수 없기 때문에
- Overflow/Underflow
  - 표현할 수 있는 값의 범위를 벗어났을 때
- 기타 Exception

## 인터럽트 동작 순서

1. 인터럽트 발생
2. 현재 프로그램 상태 백업
3. 인터럽트 처리 루틴 실행
4. 인터럽트 서비스 루틴 실행
5. 상태 복구
6. 중단된 프로그램 실행 재개

## 입출력 인터럽트와 하드웨어 구조

### 칩셋 구조

1. 과거의 메인보드는 노스브릿지와 사우스브릿지라는 칩셋 구조를 사용했다.
2. 노스브릿지는 CPU, RAM, 그래픽 카드처럼 빠른 데이터 전송이 필요한 장치를 연결했다.
3. 사우스브릿지는 USB, PCI, IDE, BIOS 같은 상대적으로 느린 주변 장치를 관리했다.

### 현대 컴퓨터 구조

1. 최근에는 노스브릿지의 주요 기능이 CPU 안으로 들어갔다.
2. 메모리 컨트롤러나 PCI Express 컨트롤러가 CPU에 통합되면서 통신 지연이 줄어들었다.
3. 메인보드의 품질이나 칩셋 구성은 확장성, 전원 공급, 입출력 성능에 영향을 줄 수 있다.

## 입출력 처리 흐름

### 입출력 요청 과정

1. 프로그램이 파일 저장, 화면 출력, 네트워크 전송 같은 입출력을 요청한다.
2. 운영체제는 시스템 콜을 통해 요청을 커널에서 처리한다.
3. 커널은 장치 드라이버를 통해 하드웨어에 작업을 요청한다.

### 주변기기의 비동기 처리

1. 성능이 좋은 주변기기나 장치 컨트롤러는 요청받은 작업을 CPU와 독립적으로 처리할 수 있다.
2. CPU는 입출력 작업이 끝날 때까지 계속 기다리지 않고 다른 작업을 실행할 수 있다.
3. 주변기기는 작업이 끝나면 인터럽트를 발생시켜 CPU에게 완료 사실을 알린다.

### 장치 드라이버

1. 장치 드라이버는 운영체제와 하드웨어 사이에서 명령을 전달하는 프로그램이다.
2. 운영체제는 장치의 세부 동작을 직접 알지 않아도 드라이버를 통해 장치를 사용할 수 있다.
3. 장치 드라이버는 하드웨어 요청, 완료 알림, 오류 처리를 운영체제에 맞게 전달한다.

### Windows XP의 GDI 기반 화면 출력

1. GDI는 Windows XP에서 처음 등장한 것은 아니지만, Windows XP의 일반적인 화면 출력에 많이 사용되었다.
2. 프로그램은 GDI 함수를 호출하고, GDI는 화면에 그릴 내용을 그래픽 장치 드라이버에 전달한다.
3. 그래픽 장치 드라이버는 전달받은 그리기 명령을 그래픽 카드가 처리할 수 있는 방식으로 바꾼다.

### DirectX

1. DirectX는 Windows에서 그래픽, 사운드, 입력 장치 같은 멀티미디어 하드웨어를 사용하기 위한 API이다.
2. 프로그램은 하드웨어를 직접 제어하지 않고 DirectX를 통해 그래픽 카드나 사운드 장치에 작업을 요청할 수 있다.
3. DirectX는 현재 Windows에서도 게임, 영상 처리, 3D 그래픽, GPU 가속 작업에 계속 사용된다.

### DMA를 사용하는 경우

1. CPU가 데이터를 하나씩 직접 옮기지 않는다.
2. 장치가 DMA를 통해 메모리에 직접 접근한다.
3. 작업이 끝나거나 오류가 발생하면 장치가 인터럽트를 발생시킨다.

### 인터럽트 발생 후 처리

1. CPU는 실행 중이던 작업의 상태를 저장한다.
2. 인터럽트 서비스 루틴을 실행한다.
3. 인터럽트 처리가 끝나면 원래 실행하던 작업으로 돌아간다.

### 정리

1. 입출력 장치는 작업이 필요하거나 완료되었을 때 인터럽트로 CPU에게 알릴 수 있다.
2. 성능이 좋은 주변기기와 장치 컨트롤러는 입출력 작업을 비동기적으로 처리해 CPU의 부담을 줄일 수 있다.
3. 장치 드라이버는 운영체제와 하드웨어 사이에서 요청과 응답을 전달한다.
4. Windows XP의 일반 화면 출력은 GDI 기반으로 처리되는 경우가 많았고, DirectX는 현재도 고성능 그래픽 작업에 사용된다.
